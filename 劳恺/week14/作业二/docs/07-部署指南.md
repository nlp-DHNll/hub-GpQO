# 07 · 部署指南

---

## 1. 服务器规格要求

| 项 | 最低 | 推荐 | 说明 |
|---|---|---|---|
| GPU 显存 | 24GB | **48GB** | Qwen3-VL-8B(bf16)≈17GB + Embedding-0.6B≈1.5GB + KV cache |
| GPU 架构 | Ampere+ | Ada / Hopper | 若要用 FP8 量化权重需 Ada+ |
| 内存 | 16GB | 32GB+ | Kafka(2G) + ES(4G heap) + 后端 + 模型加载 |
| 磁盘 | 50GB | 100GB+ | 镜像 ≈25GB + 模型 ≈20GB + 数据 |
| CPU | 4 核 | 8 核+ | ES 与图片处理 |
| 系统 | Ubuntu 22.04 | Ubuntu 22.04 / 24.04 | Docker 官方支持 |
| 网络 | 可出公网 | | 下载镜像、访问 MinerU API 与 vLLM |

**显存预算（48GB 推荐配置）**

```
Qwen3-VL-8B-Instruct (bf16)   16.0 GB  权重
                                 6.0 GB  KV cache + 激活（--gpu-memory-utilization 0.80 → 38.4GB 预算）
                                 1.5 GB  Qwen3-VL-Embedding-0.6B（独立进程或同容器）
                                ─────────
                                23.5 GB  / 48 GB  → 余 24GB，非常宽裕
```

余量很大，可以：把 `--max-model-len` 提到 65536、`--max-num-seqs` 提到 16、甚至后期加一个 Qwen3-VL-Reranker。

## 4. vLLM 启动

### 4.1 生成模型

```bash
docker run -d --name mmrag-vllm \
  --gpus all --ipc=host --shm-size=8g \
  --restart unless-stopped \
  -p 8000:8000 \
  -v /opt/mmrag/models:/models:ro \
  -e HF_HUB_OFFLINE=1 \
  -e OMP_NUM_THREADS=1 \
  vllm/vllm-openai:latest \
  --model /models/Qwen3-VL-8B-Instruct \
  --served-model-name qwen3-vl \
  --host 0.0.0.0 --port 8000 \
  --max-model-len 32768 \
  --limit-mm-per-prompt '{"image": 8, "video": 0}' \
  --mm-processor-kwargs '{"max_pixels": 1003520}' \
  --gpu-memory-utilization 0.55 \
  --max-num-seqs 16
```

> **`--gpu-memory-utilization 0.55` 的说明**：48GB × 0.55 ≈ 26GB 给生成模型（权重 16GB + KV 10GB）。剩下 22GB 留给嵌入模型与将来可能加的 reranker。若只用 24GB 卡，则这里设 0.75 且必须把嵌入模型放 CPU。
>
> **`--limit-mm-per-prompt` 与 `--mm-processor-kwargs` 必须配套**：默认每张图最多 16384 visual token；不压 `max_pixels` 就把图数提到 8，序列预留的多模态 token 预算会直接 OOM。压到 ~1MP 后每图约 1280 token，8 张约 10K，安全。

**验证**

```bash
curl http://localhost:8000/v1/models
# 应返回 qwen3-vl
```

### 4.2 嵌入模型（两种方案）

**方案 A（推荐，真实图文统一空间）**：本地 `sentence-transformers` 进程，与后端同容器或独立容器。

```python
# app/llm/embedding_client.py 内，embedding_backend="local"
from sentence_transformers import SentenceTransformer
model = SentenceTransformer("/models/Qwen3-VL-Embedding-0.6B", trust_remote_code=True)
vec = model.encode(["文本"], normalize_embeddings=True)         # 文本
vec = model.encode([PIL.Image.open(p)], normalize_embeddings=True)  # 图片
```

**方案 B（省事）**：用任意 OpenAI 兼容的文本 embedding 服务（如 bge-m3），图片路降级为 caption 文本向量。

```bash
docker run -d --name mmrag-embed \
  --gpus all --ipc=host \
  --restart unless-stopped -p 8001:8000 \
  -v /opt/mmrag/models:/models:ro \
  infinifloat/infini-embeddings-bge-m3:latest \
  --model-id /models/bge-m3 --served-model-name bge-m3 --port 8000
```

## 5. 服务编排（docker compose）

### 5.1 服务清单

| 服务 | 镜像 | 端口 | 依赖 |
|---|---|---|---|
| `kafka` | `apache/kafka:3.9.0` | 9092（仅内部） | — |
| `elasticsearch` | `docker.elastic.co/elasticsearch/elasticsearch:8.15.3` | 9200（仅内部） | — |
| `api` | 本项目 `backend` | 8080 | kafka, es, vllm |
| `worker` | 本项目 `backend` | — | kafka, es, vllm, mineru(外网) |
| `vllm` | `vllm/vllm-openai:latest` | 8000 | GPU |
| `nginx` | `nginx:alpine` | 80 | api, vllm |

### 5.2 compose 关键片段

```yaml
services:
  kafka:
    image: apache/kafka:3.9.0
    environment:
      KAFKA_NODE_ID: 1
      KAFKA_PROCESS_ROLES: broker,controller
      KAFKA_LISTENERS: PLAINTEXT://:9092,CONTROLLER://:9093
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka:9092
      KAFKA_CONTROLLER_LISTENER_NAMES: CONTROLLER
      KAFKA_LISTENER_SECURITY_PROTOCOL_MAP: CONTROLLER:PLAINTEXT,PLAINTEXT:PLAINTEXT
      KAFKA_CONTROLLER_QUORUM_VOTERS: 1@kafka:9093
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
      KAFKA_TRANSACTION_STATE_LOG_REPLICATION_FACTOR: 1
      KAFKA_TRANSACTION_STATE_LOG_MIN_ISR: 1
      KAFKA_GROUP_INITIAL_REBALANCE_DELAY_MS: 0
      KAFKA_NUM_PARTITIONS: 2
    volumes: [kafka-data:/var/lib/kafka/data]
    # 不映射端口到宿主机 → 只在 compose 网络内可达

  elasticsearch:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.15.3
    environment:
      discovery.type: single-node
      xpack.security.enabled: "false"
      ES_JAVA_OPTS: "-Xms4g -Xmx4g"
    volumes: [es-data:/usr/share/elasticsearch/data]
    # 同样不映射到宿主机

  api:
    build: ./backend
    env_file: [.env]
    command: uvicorn app.main:app --host 0.0.0.0 --port 8080
    depends_on: [kafka, elasticsearch, vllm]
    ports: ["8080:8080"]
    volumes: ["./data:/data"]

  worker:
    build: ./backend
    env_file: [.env]
    command: python -m app.pipeline.worker
    depends_on: [kafka, elasticsearch, vllm]
    volumes: ["./data:/data"]

  nginx:
    image: nginx:alpine
    ports: ["80:80"]
    volumes:
      - ./frontend/dist:/usr/share/nginx/html:ro
      - ./deploy/nginx.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on: [api, vllm]
```

### 5.3 nginx 反向代理

```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;

    # 前端静态资源
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API
    location /api/ {
        proxy_pass http://api:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

        # SSE 必需：关闭缓冲，否则流式被攒住
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 3600s;
        chunked_transfer_encoding on;
    }

    # 图片静态
    location /static/ {
        proxy_pass http://api:8080;
        proxy_cache_valid 200 1d;
    }
}
```

> **`proxy_buffering off;` 是 SSE 能否真正流式的关键**。默认开启时 nginx 会缓冲响应，前端要等整个回答生成完才一次性收到 → "流式输出"变成"一次性输出"。

## 7. 端口与安全

| 端口 | 服务 | 暴露范围 | 理由 |
|---|---|---|---|
| 80 | Nginx | **公网** | 前端 + API 反代 |
| 8080 | 后端直连 | 可选，建议仅内网/本机 | 调试用 |
| 8000 | vLLM | **不暴露公网** | 无鉴权，任何人可调模型 |
| 8001 | 嵌入服务 | 不暴露 | 同上 |
| 9092 | Kafka | **不暴露** | 无认证 |
| 9200 | ES | **不暴露** | 无认证，可读写全部数据 |

**安全组建议**：只开 `22`（SSH，限源 IP）、`80`。
其余服务全部走 compose 内部网络 + nginx 反代。

**vLLM 无鉴权的风险**：任何能访问 8000 的人都能消耗 GPU。因此**必须**不对公网开放 8000。

## 9. 运维要点

| 事项 | 建议 |
|---|---|
| 数据目录 | `/opt/mmrag/data` 挂载到宿主机，定期备份 `images/`（原 PDF 可从上传源重新获取） |
| `work/` 清理 | MinerU 解压临时目录，解析成功后即删；加 cron 清理 24 小时前的残留 |
| ES 磁盘 | `max_shard_size` 监控；单索引 ≤ 20GB 时不需要分片 |
| Kafka 磁盘 | 保留 7 天；单用户量级占用 < 1MB |
| 日志 | 后端日志输出到 stdout → `docker compose logs`；生产可接 Loki/ELK |
| 备份 | 至少备份 `mmrag-documents` / `mmrag-chunks` / `mmrag-images` 三个索引（`elasticdump`） |

```bash
# 索引备份
docker run --rm -v /opt/mmrag/backup:/backup \
  docker.elastic.co/elasticsearch/elasticsearch-dump:8.15.3 \
  --output=/backup/mmrag-chunks.json \
  http://elasticsearch:9200/mmrag-chunks
```

## 10. 本地开发（不占云端资源）

```bash
cd deploy
docker compose -f docker-compose.dev.yml up -d kafka elasticsearch

cd ../backend
python -m venv .venv && source .venv/Scripts/activate   # Windows Git Bash
pip install -e ".[dev]"

cp ../deploy/.env.example .env
# 设 MOCK_MODE=true，KAFKA_BOOTSTRAP_SERVERS=localhost:9092，ES_URL=http://localhost:9200

uvicorn app.main:app --reload --port 8080
python -m app.pipeline.worker
```

Mock 模式下 MinerU / vLLM / Embedding 都用桩实现，**不产生任何 GPU 与外网费用**，全链路（上传→状态→检索→问答→引用）可完整验证。
