## 3. 关键实现顺序（避免返工）

```
契约冻结
   │
   ├─→ ES schema ──→ 切块输出模型 ──→ 检索实现 ──→ Prompt 组装 ──→ 问答
   │      ↑                                                      ↑
   │      └──────────── content_list 字段实测 ────────────────┘
   │
   └─→ MinerU 实测 ──→ 切块规则定稿
```

> **强建议**：**先跑通一次真实的 MinerU 任务**，打印 `content_list` 的字段与 type 分布，再动手写切块代码。否则切块逻辑可能要返工（见 `05-MinerU接入.md` §5 的警告）。

## 4. 风险登记

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| `content_list` 字段与预期不符 | **高** | 切块逻辑返工 | 先实测再写码；解析代码写成字段容错 |
| MinerU 免费额度不足（1000 页/天） | 中 | 批量导入排队 | `page_ranges` 截取；分批导入；前端提示额度 |
| 单份 PDF 超 200 页 | 中 | 任务失败 | 校验页数并拒绝；或用 `page_ranges` 分段 |
| ES 中文检索效果不佳 | 中 | 召回下降 | jieba 预分词；必要时评估 IK 插件 |
| vLLM 图片显存 OOM | 中 | 问答 500 | `max_pixels` 压到 1MP；限制图片数；`--gpu-memory-utilization` 调参 |
| 图片路召回提升不明显 | 中 | 答辩说服力 | 如实分析（`openai` 后端降级导致），并演示 `local` 后端的对比 |
| 引用标记格式不稳定 | 中 | 引用缺失 | few-shot 提示 + 温度调低 + 后处理降级 |
| Worker 崩溃导致状态卡住 | 低 | 状态不一致 | offset 不提交 → 重放；文档级超时兜底 |
| 前端 SSE 被 nginx 缓冲 | 低 | 流式失效 | `proxy_buffering off` |
| 时间超期 | 中 | 交付风险 | 优先 M1→M4（可演示），M5/M6 按时间裁剪 |

## 5. 时间预算与裁剪策略

假设可用工作日 **N 天**：

| 优先级 | 内容 | 约占 |
|---|---|---|
| **P0（必做）** | M1 + M2 + M3 + M4 | 60% |
| **P1（重要）** | M5 评测（哪怕只做 15 道题） | 20% |
| **P2（加分）** | 前端交互优化、对比实验、局限性分析 | 15% |
| **P3（可选）** | 多轮对话精细化、reranker、图片路优化 | 5% |

**裁剪顺序（时间不够时按此砍）**
1. 先砍 M5 的对比实验（保留 Hit@8 与人工评分）
2. 再砍评测题量（30 → 15）
3. 再砍 D 类多轮题
4. 核心链路（M1~M4）**不砍** —— 那是"能演示"的底线

## 7. 开发规范

| 项 | 规范 |
|---|---|
| 语言 | Python 3.12，全量类型标注 |
| 注释与 docstring | **中文**（与教学材料一致，便于答辩讲解） |
| 框架 | FastAPI + Pydantic v2；HTTP 用 httpx；ES 用异步客户端；Kafka 用同步库 + 线程池包装 |
| 异步 | 全链路 async/await；阻塞调用（transformers、jieba、CPU 计算）用 `asyncio.to_thread` 包装 |
| 错误处理 | 自定义异常携带**用户可读**的中文信息；禁止裸 `except: pass` |
| 日志 | `logging` 模块，结构化上下文（doc_id/task_id） |
| 测试 | pytest；核心逻辑（切块、RRF、引用解析、Prompt 组装）必须有单测；**不依赖网络** |
| 配置 | **禁止**在代码里硬编码路径/URL/密钥，一律走 `Settings` |
| 提交 | 每个里程碑一个提交，提交信息写清模块 |

## 8. 下一步（最小启动动作）

```bash
# 1. 起基础设施
cd deploy && docker compose -f docker-compose.dev.yml up -d

# 2. 建虚拟环境
cd ../backend && python -m venv .venv && source .venv/Scripts/activate
pip install -e ".[dev]"

# 3. 【最优先】跑一次真实 MinerU 任务，dump content_list 的字段
#    → 把输出贴回来，据此定稿切块代码
```

**第 3 步是整个项目第一个真正的技术风险点**，做完它，切块与索引部分就基本没有不确定性了。
