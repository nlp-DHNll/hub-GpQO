一、 langchain 工具调用 和 llm function call 有什么区别？
--原生 Function Call	
模型 API 底层能力；
编码工作量大，所有循环、消息拼接、解析全部手动写
仅限支持 tools 的大模型
需要自己适配各家模型 API 差异
几乎无额外代码层开销	增加

--LangChain 工具调用
上层开发框架封装
create_agent/Agent 自动处理多轮循环
支持所有模型，无函数调用能力也能模拟格式适配		
LangChain 统一抽象，切换模型尽量不用改业务代码
 LangChain 中间层逻辑，带来微小性能损耗
框架内置重试、格式校验、异常捕获机制

二.langchain 工具调用 的 速度是受到什么影响？

1.大模型层面（核心）
是否原生支持 FunctionCall：原生调用更快；靠 Prompt 模拟 JSON 解析，易报错重试，速度慢。
模型推理性能：模型大小、云端负载 / 本地 GPU 算力决定推理耗时。
上下文 Token：工具注释、对话历史越长，推理越慢。
工具调用轮次：连续多次调用工具，会产生多轮 LLM 往返。
2. 网络层面（云端 API 常见瓶颈）
单次工具调用至少 2 次 LLM 请求，网络延迟、跨境 / 接口距离直接拉长耗时。
3. 自定义 Tool 本身（极易忽略）
工具内部如果存在接口请求、数据库查询、IO 操作，工具执行耗时会直接叠加总耗时。
4. LangChain 框架开销
Agent 类型：原生 Tools Agent 优于老式 ReAct 提示词 Agent；
额外组件：回调、日志、LangSmith 追踪、会话存储增加损耗；
格式解析、异常重试逻辑带来额外等待。
5. 代码配置
同步阻塞执行 vs 异步执行；
未限制最大调用轮次，可能出现无限循环；
缺少 LLM / 工具缓存，重复计算。
