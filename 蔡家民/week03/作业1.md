# 作业1答案

## 1. LangChain 工具调用 和 LLM Function Call 有什么区别？

从运行结果可以看到，LangChain 底层就是调用模型的 Function Calling 能力。

简单说：LangChain 工具调用 = 更简洁的代码写法，底层就是模型的 Function Calling。

| 对比项 | LangChain 工具调用 | LLM 原生 Function Calling |
|--------|-------------------|---------------------------|
| 本质 | LangChain 框架的封装层 | 模型厂商的原生能力 |
| 工作原理 | bind_tools() 把工具 schema 转为模型的 function calling 格式 | 直接在 API 请求中传 tools 参数 |
| 返回格式 | LangChain 解析为统一的 tool_calls 对象 | 原始 JSON（各厂商格式不同） |
| 执行方式 | 框架不执行工具，只返回调用信息，需要代码手动执行 | 同上 |
| 兼容性 | 通过统一接口适配多种模型 | 需要模型本身支持 |

## 2. LangChain 工具调用 的速度受什么影响？

从实际运行可以看出耗时主要来自以下几个因素：

- **LLM 推理时间**：模型决定调用哪些工具 + 生成回答，约 1-3 秒
- **网络延迟**：到 API 服务器的往返时间，取决于网络
- **调用次数**：完整流程需要 2 次 LLM 调用
  - ① 判断用哪些工具
  - ② 生成最终回答
- **工具执行时间**：代码执行工具的耗时（本例几乎为 0，如果是真实 API 调用会累加）
- **Token 数量**：上下文越长，推理越慢

**本例耗时 ≈ LLM × 2 次调用 + 网络延迟 + 工具执行时间**
