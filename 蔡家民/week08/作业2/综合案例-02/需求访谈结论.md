# 综合案例-02：需求访谈结论

> 状态：已确认  
> 确认日期：2026-09-10  
> 原始规格：`README.md`

## 1. 项目目标

将现有“深度研究助手”完善为一个可部署、可完整演示的个人研究工具，主要用于课堂或内部汇报。

- 产品阶段：可演示原型
- 使用者：个人单用户
- 交付形态：Web 前端 + 后端 API
- 部署方式：先完成本地 Docker Compose 部署，服务器准备后再上线
- 访问方式：共享密码保护，通过稳定免费子域名或隧道提供 HTTPS
- 核心取舍：平衡研究质量、完成速度和 API 成本

## 2. 核心流程

1. 用户输入研究主题、研究目标、时间范围、地区、报告受众和研究深度。
2. 用户选择快速、标准或深度档。
3. 系统规划检索关键词，搜索中英文公开网页并提取网页正文。
4. 页面实时展示规划、搜索、总结、充分性判断和报告生成进度。
5. 系统生成带可追溯引用的中文研究报告。
6. 用户可以查看历史、取消任务、重试失败任务并导出报告。
7. 用户可以针对已完成报告提出补充要求，生成 V2、V3 等新版本。

仅处理合法公开网页，不绕过登录、付费墙或反爬限制。正文提取失败时使用搜索摘要作为降级，并在报告中明确标注。

## 3. 研究档位与限制

| 档位 | 研究轮数 | 最长时间 | 最大搜索次数 | 模型调用上限 |
| --- | ---: | ---: | ---: | ---: |
| 快速 | 1 | 2 分钟 | 3 | 8 |
| 标准 | 2 | 6 分钟 | 8 | 15 |
| 深度 | 3 | 12 分钟 | 15 | 24 |

达到任一上限时，系统使用现有材料生成报告，并明确标记研究限制。最多并发执行 2 个任务，其余任务进入队列。

## 4. 报告要求

报告采用固定结构：

1. 摘要
2. 背景
3. 分节分析
4. 关键结论
5. 风险与局限
6. 遗留问题
7. 来源列表

正文中的关键事实必须附引用编号；来源记录 URL、标题和访问时间。所有无来源结论必须标记为“模型推断”。资料不足时仍生成报告，并展示低置信度、资料缺口和局限。

有可靠结构化数据时可以自动生成简单图表；不得编造数据或为满足版式强行生成图表。

支持以下输出：

- 网页报告
- Markdown
- HTML
- PDF

## 5. 页面与交互

前端采用专业研究工作台布局，仅适配电脑浏览器。

- 共享密码登录页
- 首页工作台
- 新建研究表单
- 运行中任务和排队状态
- 实时研究过程页
- 历史报告列表
- 报告详情和版本切换
- 简易管理页

任务完成后同时提供页面通知和浏览器桌面通知。管理页显示服务状态、任务数量、API 调用量、失败记录和数据清理入口。

取消任务后保留已完成步骤和部分结果，并将任务状态标记为“已取消”。失败任务支持重新运行。

## 6. 技术方案

- 前端：Next.js、TypeScript、Tailwind CSS
- 后端：FastAPI
- 数据库：PostgreSQL
- 数据迁移：Alembic
- 任务队列：Redis + Celery
- Worker 并发数：2
- 进度推送：Server-Sent Events，轮询作为降级方案
- 模型：现有 DeepSeek 兼容接口
- 搜索：Bocha 网页搜索
- 网页读取：提取公开网页正文，失败时使用搜索摘要
- PDF：通过自包含 HTML 渲染
- 部署：Docker Compose + HTTPS 反向代理
- 测试：后端单元测试、集成测试、模拟外部服务测试和关键页面端到端测试

## 7. 安全和运行要求

- 共享密码以哈希形式存放于服务器环境变量中。
- 登录成功后签发 24 小时有效的 Secure、HttpOnly Cookie。
- 登录、创建任务等接口实施速率限制。
- API Key 只通过环境变量注入，不进入代码、镜像、日志或版本库。
- 删除现有文档中的明文凭据，提供不含真实值的 `.env.example`。
- 现有已暴露凭据不得继续用于正式部署。
- 网页内容视为不可信输入，防范提示词注入、SSRF、危险重定向和恶意 HTML。
- 用户页面只展示友好错误和重试入口；详细错误进入结构化日志和管理页。
- 服务重启后，排队或运行中的任务应能够恢复或被安全标记后重试。

## 8. 数据和版本

- 研究记录默认永久保存，用户可以手动删除。
- 取消任务后保留已完成步骤和部分结果，状态标记为“已取消”。
- 失败任务支持重新运行。
- 补充研究不覆盖原报告，而是生成 V2、V3 等版本。
- 搜索来源按 URL 去重，并保存标题、摘要、正文提取状态和访问时间。

## 9. 验收标准

使用至少 3 个不同类型的主题验收：

- 标准档任务在 6 分钟内完成。
- 新建、排队、取消和失败重试均有效。
- 研究步骤和当前进度实时可见。
- 报告使用固定结构，关键事实具有可打开的来源引用。
- 无来源推断、低置信度和资料缺口得到明确标记。
- Markdown、HTML 和 PDF 可以正常导出和打开。
- 可以对已完成报告发起补充研究，并切换查看不同版本。
- Docker Compose 可以在新机器上按文档启动。
- 代码、镜像、导出文件和日志中不包含真实密钥。

## 10. 本期不做

- 多用户账户和企业多租户
- 手机端适配
- 用户指定网址
- 文件上传和企业内部知识库
- 在线编辑报告正文
- 邮件通知
- 多模型或多搜索供应商切换
- 正式压力测试
- 当前阶段的公网服务器部署
