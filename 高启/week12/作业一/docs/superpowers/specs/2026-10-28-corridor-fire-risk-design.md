# 楼道消防隐患识别网页应用设计

## 意图

基于案例 `案例-多模态内容理解.ipynb` 中的楼道风险分类规则，构建一个能通过手机浏览器拍照或选择图片的独立网页应用。后端将图片发送给 DeepSeek `deepseek-flash` 视觉接口，返回楼道识别结果、风险等级、判断依据和处置建议。

## 目标

- 手机网页可请求摄像头拍照，也可从相册选择图片；桌面端可用文件选择上传。
- 后端校验图片格式和大小，使用服务端环境变量中的 API Key 调用 DeepSeek 视觉接口。
- 结果类别为：非楼道、无风险、低风险、中风险、高风险。
- 页面清楚展示等级、原因和建议，并在模型调用或图片校验失败时展示中文提示。
- 提供中文 README（依赖、配置、启动、手机访问方式）及中文代码注释。

## 非目标

- 不训练或部署本地视觉模型，不保存用户上传图片或建立历史记录。
- 不承诺替代消防专业人员检查；模型输出用于辅助巡查。
- 不做账号、数据库、告警推送或多用户管理。

## 风险分类约束

- **高风险**：楼道中出现电动车、电瓶、飞线充电等可能引发火灾的因素。
- **中风险**：大量堆物严重影响通行，或纸箱、木家具等可燃物堆放形成明显堵塞、助燃条件。
- **低风险**：有少量或不严重的楼道堆物。
- **无风险**：确认是楼道且干净、无堆放物。
- **非楼道**：无法确认属于楼道的图片。
- 若图像模糊、遮挡或证据不足，模型应说明不确定性，并保守地给出需人工复核提示，不能伪称已确认安全。

## 实现方式与取舍

1. **独立网页应用（选定）**：Python 后端同时提供网页和识别接口。结构简单，适合本地启动并通过局域网手机访问；服务端密钥不会暴露给浏览器。
2. **Notebook 外包网页**：能复用本地 Qwen-VL 推理，但依赖 notebook/本地模型环境，不符合本次指定的 DS Flash 调用与独立网页体验。

## 架构与交互

- 使用 FastAPI 提供静态网页和 `POST /api/analyze` 图片识别接口。
- 网页提供“拍照”和“选择图片”入口、图片预览、识别按钮、加载状态及结果卡片。
- 手机拍照通过支持移动浏览器的文件输入（`accept="image/*"`、`capture="environment"`）实现；若浏览器不支持直接调起摄像头，用户仍可从相册选择。
- 后端用 DeepSeek 官方 OpenAI 兼容 Chat Completions API 的图片输入格式，将图像作为 data URL 随请求发送；不先上传到第三方文件托管。
- 模型返回 JSON 结果，后端校验类别和必需字段后返回给网页。API 地址、模型名可用环境变量配置，默认值按官方视觉 API 当前约定设置。
- 上传大小设置合理上限，校验 MIME/文件头，限制 API 超时；错误转换为清晰的中文消息。
- 在 multipart 解析前限制请求体大小，并设置按客户端 IP 的请求频率和并发上限，减少局域网误用导致的费用消耗。

## 配置与隐私

- `.env.example` 展示 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL` 等配置项；真实密钥不得写入源码或提交到版本库。
- 图片只在请求期间处理，不写入持久存储；默认不记录图片内容或密钥。
- README 说明安装、启动、密钥配置及手机通过同一局域网访问的步骤。
- README 提醒局域网内设备可访问服务，并说明请求频率与并发限制范围。

## 验收标准

- 安装依赖并配置 API Key 后，可启动网页服务。
- 桌面端上传图片、手机端拍照/相册选图均能触发识别。
- 五种类别均映射为约定中文风险标签，页面展示判断依据和建议。
- 非图片、超限图片、缺少密钥、上游错误和超时均有明确中文反馈。
- README 与源代码注释使用中文；不在仓库中包含真实密钥。

## 由实现者决定

目录与模块的具体拆分、页面视觉细节、请求超时和图片大小默认值、具体提示词措辞。实现者应保持依赖精简，并遵循 DeepSeek 官方 API 的现行多模态请求格式。
