# 有确定性 script 对比没有 script：两个 ESG skill 的实测对比

作业1 的两个 skill 只有 `SKILL.md` 和 `references/`，检索、抓取、筛选、提炼、统计、合成、复核全部由 agent 即兴完成；作业2 是同一套 skill 的脚本版，把确定的环节交给 `scripts/` 里的 10 个脚本，agent 只做检索计划、判断取舍和写作。两版用同一个复核脚本 `check_report.py` 量。

## 一、实验设置

- 同一台机器、同一天（2026-11-26）、同样的 references 和报告模板；检索工具同为内置搜索；提炼模型同为 deepseek-chat。
- 案例一：中国神华，2026-10-27 至 2026-11-26 的 ESG 月报。
- 案例二：ESG 招投标回顾 2024-11-27 至 2026-11-26，加最近 7 天监控日报。
- 每版各跑 1 次。作业1 的两份报告是最新版 skill 跑出的结果（此前迭代过一轮，见 job1 输出里的 `_run1`）。
- 无搜索 API key，脚本版的搜索由 agent 用内置搜索导出结果、再由 `search.py --provider file` 归一化去重。

## 二、客观指标（`check_report.py` 计算）

| 指标 | 无 script（作业1） | 有 script（作业2） |

| 悬空引用 | 0 | 0 |

| 事实单元带引用 | 36/52，69.2% | 61/66，92.4% |
| 正文字数 | 4985 | 5985 |
| 缺失章节 | 无 | 无 |

## 三、过程与成本

| 指标 | 无 script | 有 script |
|---|---|---|
| 月报：内置搜索次数 | 30 | 30 |
| 月报：agent 打开网页次数（成功） | 16（11） | 5（2） |
| 月报：脚本抓取原文 | 无 | 202 条（成功 134、失败 14） |
| 月报：提炼调用 | agent 逐条阅读，27 条采信 | 90 张卡，大模型 119.5k 输入 + 22.8k 输出 token |
| 月报：耗时 | 18.6 分钟 | 30.6 分钟 |
| 月报：子代理累计 token | 5.68M | 21.1M |
| 招标：内置搜索次数 | 42（回顾 30 + 监控 12） | 回顾 30；监控阶段按 SKILL.md 预算不超过 12 次 |
| 招标：读取原文次数（成功） | 21（14） | 脚本抓取 54（成功 46）+ agent 5（2） |
| 招标：耗时 | 24.1 分钟 | 约 29 分钟 |
| 招标：子代理累计 token | 11.1M | 未单独记录 |
| 监控：日报新增 | 招标 6、中标 2 | 招标 10、中标 2 |
| 监控：能否无人值守 | 不能，每次要有 agent 会话 | 能，`monitor.py` 纯规则模式不调大模型，可挂计划任务 |

成本口径需要说明：子代理累计 token 包含每一轮重复读取的上下文，脚本版回合更多（迭代了抓取上限、补搜），累计值反而更高；而"逐篇阅读"的文本量确实从 agent 上下文搬到了脚本里（月报 90 篇只用 14 万 token，若人工逐篇读完约 45 万 token 进上下文）。所以"省 token"不能只看一个口径。

## 四、报告质量

人工通读与两轮盲评（去掉附录后交给大模型按六个维度打分，A、B 顺序每轮互换）结果：

| 维度 | 月报 无 script | 月报 有 script | 招标 无 script | 招标 有 script |
|---|---|---|---|---|
| 结构完整性 | 4.5 | 5.0 | 5.0 | 5.0 |
| 事实可追溯 | 3.5 | 4.0 | 4.0 | 4.0 |
| 分析深度 | 3.5 | 4.5 | 4.5 | 4.0 |
| 建议可操作性 | 4.5 | 4.5 | 4.0 | 3.0 |
| 数据准确性 | 3.5 | 4.0 | 4.0 | 3.5 |
| 可读性 | 4.5 | 4.5 | 4.5 | 4.5 |
| 合计 | 24.0 | 26.5 | 26.0 | 24.0 |

差异在哪，人工复核的结论：

- 月报：脚本版多挖出矿山安监局 11 月 9 日信息化系统建设通知（含 95% 识别率、10 人报警、2027 年 6 月底建成等硬指标）、证监会《可持续发展报告电子化规范》298 项元素、申万宏源煤炭央企 ESG 评价体系，公司动态用上了神华官网原文；纯指令版这 4 条都没抓到，且 15/25 条来源只能依据搜索摘要。
- 招标：纯指令版的语料更大（65 条来源、39 条中标），结论里的价格带和机构格局更细，建议也更具体；脚本版统计与正文零误差、图表齐全，但抓取失败多（54 条里 8 条失败）导致样本偏小，建议部分（买方/服务商两段）被盲评认为不够可操作。

## 五、结论

1. 确定性的环节交给脚本，效果是"更稳"：来源可核验率月报从 72% 升到 97%、招标从 68% 升到 72%；事实单元带引用率从 69% 升到 92%、从 54% 升到 98%；悬空引用两版都是 0，但脚本版的数字一致性和图表靠代码保证，不再依赖 agent 手工统计。
2. 脚本带来的增量主要在"读不到"和"重复劳动"：纯指令版的 agent 用服务端网页读取，神华官网、国资委等站点读不了；脚本用本机抓取补上了这些来源（月报 25 条来源里 15 条只能看摘要，脚本版 37 条里 36 条可核验）。时间窗过滤、去重、页面类型识别、统计画图这些动作，脚本每次都一致。
3. 纯指令版不一定差：它的内置搜索覆盖面和"临场换检索式"的能力很强，招标报告靠这个拿到了更大的语料和更好的建议。脚本版的搜索能力受限于搜索源（本次只能靠 agent 导出结果），配上搜索 API key 后才真正体现"脚本自己搜"。
4. 成本上，脚本版省的是"逐篇阅读进上下文"的 token，费的是前期工程（10 个脚本约 2100 行）和更多回合。适合定期跑、多人复用的场景；一次性的临时研究，纯指令版更快。

## 六、局限

- 每版只跑了 1 次（月报的纯指令版跑了 2 轮），样本小，盲评 2 轮；结论是方向性的。
- 脚本版本次实跑用的是修正前的默认参数（抓取上限 80、关键词未覆盖客户/对标主体），这两项已修进交付的脚本（上限 200、主体别名不受分数限制），修好后脚本版的语料和覆盖还会提高；未再重跑以控制时间与额度。
- 搜索 API（博查、Tavily、Serper）的 provider 代码未实测（本机无 key）；`monitor.py` 的无人值守模式依赖搜索 API key。
- 复核脚本的"可核验"依赖本机网络可达性，打不开的页面按"无法解析/打不开"单列，不与"内容造假"混同。

## 附：实验可复现

- 复核：`python esg-monthly-report/scripts/check_report.py --report <报告> --sources <来源> --out check.json --since <起> --until <止> ...`
- 盲评：`python judge.py --a <作业1报告> --b <作业2报告> --out judge.json --repeat 2`（结果见 `output/judge_monthly.json`、`output/judge_bidding.json`）
- 各脚本的统计行、修正记录分别见两版输出目录的 `trace.md`。
