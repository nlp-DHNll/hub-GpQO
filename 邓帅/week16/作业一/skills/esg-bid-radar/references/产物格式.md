# 招投标情报的产物格式

汇总报告、日报的骨架，招标记录与运行记录的模板。运行产物契约的权威说明在 `邓帅/week16/tools/readme.md`，
本文件是其中招投标部分的摘录，两者不一致时以它为准。

## 汇总报告的骨架 `report.md`（汇总模式）

把尖括号里的内容换成实际值，括号里的提示写完后删掉。

```markdown
# ESG 相关招标两年汇总（<起始日期> 至 <结束日期>）

- 时间窗：<起始日期> 至 <结束日期>（N 个月）
- 样本量：N 条范围内中标公告
- 来源构成：中国政府采购网 N 条、各省公共资源交易中心 N 条、其它 N 条
- 金额可得率：N%（a/b）

（两三句结论：哪些主题在放量、金额大致什么量级。写明这是样本，不是全量普查）

## 一、热点主题排行

| 排名 | 主题 | 样本数 | 中标金额合计 |
|---|---|---|---|

## 二、金额分布

| 金额区间 | 样本数 |
|---|---|

## 三、月度趋势（按季归并）

| 季度 | 中标公告数 |
|---|---|

## 四、采购人类型与地区分布

| 采购人类型 | 样本数 | 地区 | 样本数 |
|---|---|---|---|

## 五、典型项目

| 序号 | 项目 | 采购人 | 中标金额 | 链接 |
|---|---|---|---|---|

## 六、方法与来源说明

（实际检索次数与检索词；样本怎么选出来的；哪些主题或站点没有覆盖到；局限）

## 附录：边界外招标

（一句说明：与 ESG 沾边但不属于专业服务，只作线索，不进上面的统计；没有边界外招标就写明原因）

| 序号 | 项目 | 采购人 | 主题 | 链接 |
|---|---|---|---|---|
```

章节靠标题里的关键词识别，标题里的这些词不能省：

| 章节 | 标题须含有 |
|---|---|
| 热点主题排行 | 主题，且含「热点」或「排行」 |
| 金额分布 | 金额、分布 |
| 月度趋势 | 趋势、月 |
| 采购人类型分布 | 采购人、类型（可与地区分布合成一节） |
| 地区分布 | 地区 / 省份 / 地域 任一 |
| 典型项目 | 典型 / 案例 任一 |
| 边界外招标附录 | 边界外 |

每一节都要有内容。边界外招标（`in_scope` 为 `false` 的记录）的链接**只能出现在附录里**，正文其它位置（包括开头的来源构成、
方法说明）都不要放它们的链接；附录也不能漏列任何一条边界外记录。

## 日报的骨架 `report.md`（监控模式）

```markdown
# ESG 招标监控日报（<结束日期>）

- 基线：<起始日期>
- 时间窗：<起始日期> 至 <结束日期>
- 新增：N 条
- 覆盖范围：中国政府采购网、某省公共资源交易中心、某招标信息平台；关键词「碳排放核算」「ESG 报告」「碳资产」（哪些站点或主题没检索到也写在这里）

## 新增招标公告

### 1. <公告标题>

- 采购人：<采购人全称>
- 发布日期：<YYYY-MM-DD>
- 截止日期：<原文写法；取不到写「未见」>
- 链接：<公告地址，一字不差地写全>
- 摘要：<一句话：买什么、规模多大>
```

没有新增时照常出日报：`- 新增：0 条`，正文写一句「本期无新增招标公告」，覆盖范围照写，再说一下检索了什么。

日报没有固定章节，要求是：注明 `覆盖范围`；每条新增招标的链接都原样出现在正文里（每条都有采购人、发布日期、截止日期、一句话摘要）。

## 招标记录 `data.json`

顶层是对象，记录放在 `records` 数组里。每条十三个字段都要有，不要删字段。`title`、`url`、`notice_type`、`in_scope`、`verification` 必填；
其余取不到的写 `null`。

| 字段 | 含义 | 要求 |
|---|---|---|
| `title` | 标题 | 公告标题 |
| `url` | 来源地址 | 公告原始地址，`http://` 或 `https://` 开头 |
| `notice_type` | 公告类型 | `tender`（招标公告）/ `award`（中标公告）/ `other`（其它） |
| `published_at` | 发布日期 | `YYYY-MM-DD`；页面不显示日期就写 `null` |
| `purchaser` | 采购人 | 全称 |
| `region` | 地区 | 省级行政区，如 `江苏`、`北京` |
| `topic` | 主题标签 | 范围内用六类名称之一；边界外自由填写 |
| `in_scope` | 是否在范围内 | `true` / `false` |
| `amount` | 中标金额 | 换算成元的数值，如 `1900000`；取不到写 `null` |
| `amount_text` | 金额原文写法 | 如 `190万元`；取不到写 `null` |
| `winner` | 中标人 | 可得时才有，否则 `null` |
| `source_site` | 来源站点 | 如 `中国政府采购网` |
| `verification` | 核实状态 | `verified`（已核实）/ `summary-only`（仅见摘要）/ `excluded`（已排除） |

```json
{
  "records": [
    {
      "title": "某市重点企业碳排放核算与核查服务采购项目中标公告",

    },
```

### 日报的记录

监控模式下每条在十三个字段之外还要有两个字段：`deadline`（截止日期，保留原文写法，取不到写 `null`）与 `summary`（一句话摘要，非空）。
日报里只会有招标公告（`notice_type` 为 `tender`）。

```json
{
  "records": [
    {
      "title": "某市 2026 年度重点企业碳排放核算与核查服务采购",
      "url": "http://www.ccgp.gov.cn/cggg/dfgg/zbgg/202611/t20261125_3001.htm",
      "notice_type": "tender",
      "published_at": "2026-11-25",
      "purchaser": "某市生态环境局",
      "region": "北京",
      "topic": "碳排放核算与核查",
      "in_scope": true,
      "amount": null,
      "amount_text": null,
      "winner": null,
      "source_site": "中国政府采购网",
      "verification": "verified",
      "deadline": "2026-12-05",
      "summary": "对全市重点排放企业开展年度碳排放核算与核查，服务期一年。"
    }
  ]
}
```

## 已见清单与快照

- 已见清单（如 `runs/seen/esg-bid-radar.json`）与快照 `seen_before.json` 用同一种格式：招标记录数组，或含 `records` 数组的对象。
- 快照是运行前已见清单的原样副本；清单不存在时写 `{"records": []}`。
- 运行结束后把本次新增的记录追加到已见清单，旧条目原样保留。

## 运行记录 `run.json`

无头运行由运行器生成，不要自己写。在交互会话里运行时，照下面的模板自己写一份，放在运行目录里：

```json
{
  "run_id": "20261127-手动-bid-summary",
  "case": "bid-radar",
  "mode": "summary",
  "version": "noscript",
  "skill_version": "esg-bid-radar@0.1.0",
  "client": null,
  "industry": null,
  "time_window": {"start": "2024-11-27", "end": "2026-11-26"},
  "model": "glm-5.4",
  "started_at": "2026-11-26T10:00:00+08:00",
  "duration_ms": null,
  "input_tokens": null,
  "output_tokens": null,
  "cost_usd": null,
  "search_count": 20,
  "invocation": "interactive"
}
```

监控模式的 `mode` 写 `monitor`，`time_window` 的 `start` 是基线日。
