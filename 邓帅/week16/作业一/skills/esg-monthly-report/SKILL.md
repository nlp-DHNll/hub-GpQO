# ESG 月报

## 概览

给定客户与时间窗，自主联网检索、筛选、成文，产出一份结构固定、逐条可溯源的 ESG 月报，连同证据表写进运行目录。

核心原则：**每条进结论的事实，背后都有一条打开原文核对过的证据；核对不了的如实标为待核实，不用传闻、不用时间窗外的信息填充。**

## 何时触发

使用者要为某家企业出一份 ESG 月报时触发：点名了本 skill（「用 esg-monthly-report 给某客户做近 N 天的 ESG 月报」），
或者说「出一份某客户的 ESG 月报」「汇总这个月与客户相关的 ESG 动态并给出建议」。

下面三种情况不触发：要的是招投标情报（用 esg-bid-radar）；只查一个事实；要的是跨越数月的年度报告。

## 参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| 客户 | 中国神华 | 报告的服务对象 |
| 行业 | 煤炭·能源 | 决定行业检索词与对标企业 |
| 时间窗 | 成文日前 30 天 | 起止日期；发布日期落在窗内的证据才算本期事实（对标企业的最新披露除外，见「成文规则」） |
| 搜索预算 | 40 次 | `web_search_prime` 的调用上限；读页不计 |
| 对标企业 | 按规则提出 | 同行业、规模相当、ESG 披露完善；请求可以指定 |
| 运行目录 | 见「三件产物」 | 三件产物写到那里 |

请求里显式给出的值优先于默认值。无头运行的提示词若已给出客户、行业、时间窗与运行目录，以提示词为准。
实际使用的客户、行业、时间窗写在报告开头（见「成文规则」）。

## 流程

1. 定参数，列出查询矩阵（见「查询矩阵」）。
2. 按矩阵检索，对拟采用的来源逐条读原文，登记证据（可信度分级、核实状态）。
3. 来源不足的部分换词补搜，直到够数或预算用完。
4. 按固定结构成文，事实句末加角标。
5. 写 `report.md` 与 `data.json`，按「写完后的自查」逐项过一遍。

## 检索工具约定

| 用途 | 工具 | 约定 |
|---|---|---|
| 搜索 | `web_search_prime`（智谱搜索） | 主用。`location` 设 `cn`；时间过滤取 `oneMonth`（近一个月）以保证召回，是否落在时间窗内由你逐条读发布日期判断。检索英文来源时 `location` 设 `us`、用英文检索词。`content_size` 用 `medium`。 |
| 读原文 | `webReader`（智谱读页） | 对拟采用的每条来源读原文，核对发布日期与摘录。 |
| 补充搜索 | `WebSearch`（内置网页搜索） | 只在智谱搜索没有结果时补充；结果多是跳转链接，须读原文核对。 |
| 网页抓取 | `WebFetch`（内置网页抓取） | 禁用：对中国域名不可用。 |

读页工具抓不了带中文编码参数的地址（链接里出现 `%` 编码的中文时返回 -400）。遇到这种地址，按顺序试：
换同一内容的另一个来源（发布机构的原文页、官方转载页）；从搜索结果里取该站点的可访问链接重搜；都读不到就只用搜索摘要，
把它登记为「仅见摘要」，进「待核实事项」。不要自己拼接或解码地址。

**子代理**：默认由你自己完成检索与成文。预算接近上限或矩阵很大时，可以派子代理分担检索，同时运行的不超过 3 个；
每个子代理负责矩阵中的一部分，回传来源地址、发布日期、原文摘录、可信度分级与核实状态，由你统一读原文核实后再登记。

## 查询矩阵

三大部分 × E/S/G × 中英文，先广后深。每一格至少一条中文、一条英文检索词，共 18 次；剩余预算用于深挖与补搜。

| 部分 | E（环境） | S（社会） | G（治理） |
|---|---|---|---|
| 政策/评级/标准动态 | 碳排放、环保、能效政策；环境维度评级；排放披露标准 | 安全生产、员工与社区相关政策；社会维度评级 | 披露准则、公司治理与合规监管；治理维度评级 |
| 行业新闻与最佳实践 | 行业碳中和、节能降碳案例 | 安全生产、员工责任、供应链管理案例 | 行业治理、供应链披露、反腐败实践 |
| 客户公司动态 | 客户的碳排放、环保投入、环境事件 | 客户的安全生产、员工、社区动态 | 客户的治理结构、合规、重大公告 |

检索词的写法：中文用「客户名 + 主题词」（如「中国神华 碳排放」），英文用「客户英文名 + 主题词」（如 `China Shenhua carbon emissions`）。
英文来源优先找评级机构（MSCI、Sustainalytics、S&P Global）、准则制定方（ISSB、交易所）与客户的投资关系页。
只有检索对标企业的最新披露时，时间过滤可以放宽到 `oneYear` 或 `noLimit`——要找的是它们最近一份报告，不是本期新闻。

**小预算运行**（请求写明了更小的搜索预算）：按比例压缩，三大部分每部分至少 2 次（中英文各 1），
并在「方法与来源说明」写明实际次数与没有覆盖到的格。

**换词补搜**：某一部分的合格来源（一级或二级，且核实状态为已核实或仅见摘要）少于 5 条时，换同义词、换角度、换语种再搜，
直到够数或预算用完。仍然不足，就在正文如实写明空白与原因。

## 可信度分级与核实状态

| 可信度分级 | 来源 | 用法 |
|---|---|---|
| 一级 | 政府、监管、交易所、国际组织、企业公告与官网 | 可作依据 |
| 二级 | 主流财经媒体、行业媒体、官方平台的转载或聚合 | 可作依据 |
| 三级 | 自媒体、营销号 | 只作线索；须有一级或二级佐证才能进结论 |

| 核实状态 | 含义 | 去向 |
|---|---|---|
| 已核实 | 打开过原文，核对了发布日期与摘录 | 可进结论 |
| 仅见摘要 | 只看到搜索摘要，没读到原文 | 只进「待核实事项」 |
| 已排除 | 打开后发现不适用：发布日期在窗外、与客户无关、无法溯源 | 不进结论；可在待核实事项里注明原因 |

核实时以原文页面上的发布日期为准；搜索引擎标注的「N 天前」是索引时间，不是发布日期。
原文摘录逐字取自读到的原文，不超过 50 字。

## 成文规则

报告的固定结构、章节标题与完整模板见 `references/产物格式.md`。要点：

- 章节顺序固定：摘要与本月要点 → 政策/评级/标准动态 → 行业新闻与最佳实践 → 客户公司动态的影响与建议
  （其中含对标企业关键行动对比表）→ 下月关注清单 → 方法与来源说明 → 待核实事项 → 证据表附录。
- 报告开头先写三行声明，每行一个标签：`- 客户：…`、`- 行业：…`、`- 时间窗：起始日期 至 结束日期（N 天）`。
- 每条事实的句末加角标 `[n]`，n 是证据表里的角标编号。正文角标与证据表一一对应：每个角标恰好对应一条证据，每条证据至少被引用一次。
- 摘要与本月要点每条带角标；建议落到客户的具体情况，依据用角标给出。
- 某部分确实没有时间窗内的动态（如评级未调整），写明「本期未发现」并说明检索了什么。
- 对标企业由你按规则提出至少 3 家并写明理由，本期没有它们的新行动也照常列出。行动取自其最新的 ESG 报告或官网，
  这类证据的发布日期在时间窗外属正常；没有新行动就写最近一次披露的行动，不换成不对标的企业。
- 「待核实事项」单列每条仅见摘要的证据与原因；没有待核实项就写一句「本期无待核实事项」。
- 正式运行的正文 5000–8000 字（不含证据表附录）；请求写明是小预算的骨架运行时不要求字数。
- 证据的发布日期统一写成 `YYYY-MM-DD`，不要照抄页面上的「Nov 24, 2026」「3 天前」这类写法。
- 原文摘录不超过 50 个**字符**，中英文都按字符数算——英文一句话动辄七八十个字符。取 30–40 个字符的短语，给数错留出余量。

## 三件产物

写到运行目录（无头运行由提示词给出；交互运行默认 `邓帅/week16/runs/<YYYYMMDD-HHMMSS>_monthly-report_noscript/`）：

| 文件 | 内容 |
|---|---|
| `report.md` | 报告正文，末尾附证据表附录（表格第一列是角标编号） |
| `data.json` | 证据表：`{"evidence": [...]}`。每条含 `id`、`section`、`claim`、`url`、`published_at`、`quote`、`credibility_tier`、`verification` 八个字段，一个都不能少；发布日期取不到写 `null` |
| `run.json` | 运行记录。无头运行由运行器生成，不要自己写；交互运行按模板自己写 |

字段含义与样例见 `references/产物格式.md`。

## 写完后的自查

逐项过一遍，有问题就改完再结束：

1. 报告开头三行声明的客户、行业、时间窗与本次运行一致。
2. 八个章节齐全、顺序正确，对标企业关键行动对比表是一张表格。
3. 正文每个角标都能在证据表里找到唯一一条；证据表每条都在正文出现过。
4. 证据表每条八个字段齐全，`quote` 不超过 50 个字符（英文也按字符数）且逐字出自原文。
5. 只有「已核实」的证据进结论；「仅见摘要」与「已排除」的只出现在待核实事项。

## 常见错误

| 错误 | 后果 | 改法 |
|---|---|---|
| 把搜索引擎的「N 天前」当发布日期 | 窗外信息混进本期事实 | 以原文页面的日期为准；读不到原文就标「仅见摘要」 |
| 评级或对标没有窗内结果，就拿窗外信息或不对标的企业填充 | 对比表失真 | 按规则列出对标企业，如实写「本期未见新行动」 |
| 三级来源当依据 | 结论不可靠 | 找一级或二级佐证，找不到就进待核实事项 |
| 角标悬空，或证据没有被引用 | 角标与证据表对不上 | 成文后按角标逐个核对 |
| 读页失败后凭摘要写摘录 | 摘录不是原文 | 摘录只从读到的原文里逐字取 |
| 摘录超长（尤其中文的一句话、英文的半句话） | 验收器判这条证据不合规 | 只取 30–40 个字符的短语 |
