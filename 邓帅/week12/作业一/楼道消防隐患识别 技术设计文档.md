### 2.2 levels.py——归一化定稿（T5）

```python
Level = Literal["high", "medium", "low", "none", "not_corridor"]

# 有序别名表：按序做子串匹配，首个命中即返回
ALIASES: list[tuple[str, Level]] = [
    ("非楼道", "not_corridor"),
    ("无隐患", "none"),
    ("无风险", "none"),
    ("无堆物", "none"),
    ("干净",   "none"),
    ("高风险", "high"),
    ("中等风险", "medium"),
    ("中风险", "medium"),
    ("低风险", "low"),
]

def normalize(raw: str) -> Level | None:
    text = raw.strip().strip("\"'“”·。！! ")   # 去首尾空白与常见收尾符
    for alias, level in ALIASES:
        if alias in text:
            return level
    return None
```

- 顺序规则：**特异长的词在前**（`非楼道`/`无X` 系先于 `高/中/低`，`中等风险` 先于 `中风险`），保证"该楼道无风险"命中 none 而非其他；
- 精确输出五个枚举词是其子集情形，无需单独分支；
- 已知局限：否定式输出（如"不干净"）会误命中——prompt 已约束直接输出类别词，实测出现再补负向排除，先不预设（T5 备注）；
- 此表即归一化的**单一事实源**，测试用例锁定其行为（§4.2）。

### 2.3 llm.py——vision 调用格式

沿用 week11 llm.py 模式（模块级共享客户端），消息结构按 PRD §8 已实测可用的 OpenAI 兼容图片格式：

```python
resp = await _client.chat.completions.create(
    model=settings.base_model,
    messages=[{
        "role": "user",
        "content": [
            {"type": "text", "text": RECOGNIZE_PROMPT},
            {"type": "image_url", "image_url": {"url": data_url}},  # data:image/jpeg;base64,...
        ],
    }],
    temperature=0.0,   # T8：分类任务取确定性输出
)
return (resp.choices[0].message.content or "").strip()
```

超时由客户端构造参数 `timeout=settings.llm_timeout`（30s，S7）控制，到点抛 `openai.APITimeoutError`。

### 2.4 api/routes.py——请求处理流程（T6、T7）

`POST /api/recognize`，参数 `image: UploadFile`：

1. **校验**（S5）：`content_type ∈ {image/jpeg, image/png, image/webp}` 且 `size ≤ 10MB`；违例 → `400 {"error": {"code": "INVALID_FILE", "message": "仅支持 jpg/png/webp 图片，且不超过 10MB"}}`；
2. 读 bytes → base64 → 拼 `data:{content_type};base64,...`（mime 用上传文件自带 content_type）；
3. 调 `llm.recognize_image(data_url)`：
   - `APITimeoutError` → **不重试**，`504 MODEL_TIMEOUT`（S7 语义＝超时即终止）；
   - 其他 `openai.OpenAIError` → `502 MODEL_UNPARSABLE` 兜底（T7：非超时的模型侧故障共用"识别失败"语义与文案）；
4. `normalize(raw)` 命中 → `200 {"level": "..."}`；
5. 未命中 → **重试 1 次**（S6，同 prompt 原样重发）→ 命中即 200；
6. 仍失败 → `502 MODEL_UNPARSABLE`；
7. 全程：`logging.info` 留档模型原始输出（S3）；图片 bytes 仅存内存，不落盘（S10）。

错误响应用 `JSONResponse` 直接返回（T6：单接口不值得自建异常层），body 结构遵守 PRD §6.1。

## 3. 前端设计

### 3.1 App.vue——状态机实现（T9）

纯 `ref` 状态机，不引状态库。字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `phase` | `Ref<Phase>` | `empty / preview / recognizing / result / error` 五态 |
| `imageSource` | `Ref<ImageSource \| null>` | `camera / album`，驱动按钮文案与回跳（U6） |
| `imageFile` | `Ref<File \| null>` | 压缩后唯一图片对象，失败态不清空 |
| `level` / `error` | `Ref<Level \| null>` / `Ref<ApiError \| null>` | 结果/失败载荷 |
| `cameraAvailable` | `boolean` | `onMounted` 一次性探测缓存（功能设计 §2.2） |
| `cameraSheetOpen` | `boolean` | 取景层展开开关 |
| 隐藏 `<input type="file">` | —— | **单例放 App.vue**（T10）：空态入口、U6 回跳、失败态"重新选择"共用一个 input，change 后清空 value（U9） |

动作函数 ↔ 状态转换（转换语义以功能设计 §1.2 为准）：

| 函数 | 触发点 | 效果 |
|---|---|---|
| `openCamera()` | EmptyState「拍照」 | `cameraSheetOpen = true` |
| `openAlbum()` | EmptyState「相册上传」 | 触发隐藏 input click |
| `onImageReady(file, source)` | CameraSheet 截帧后 / input change | `useCompress` 压缩 → 置 `imageFile/imageSource` → `phase = preview`；压缩后 >10MB 直接 `error`（功能设计 §2.6） |
| `confirmRecognize()` | PreviewConfirm「确认识别」 | `phase = recognizing` → `await api.recognize(imageFile)` → 成功置 `level` 转 `result`；异常置 `error` 转 `error` |
| `cancelPreview()` | 「取消」 | 清空 `imageFile/imageSource` → `empty` |
| `retakeOrReselect()` | 「重拍/重选」 | `camera` → 开取景层；`album` → 触发 input click；替换后经 `onImageReady` 停留 `preview`（取景层中途关闭不动旧图） |
| `retryRecognize()` | ErrorPanel「重试」 | 同一 `imageFile` 重走 `confirmRecognize()` |
| `reopenSource()` | 「再拍一张」「重新选择」「重新拍摄」 | 回 `empty` 后直接调起原来源（U6）：`camera` 且 `cameraAvailable` → 开取景层，否则 → input click |

### 3.3 组件签名（props ↓ / emits ↑，T9 不引 pinia）

| 组件 | props | emits |
|---|---|---|
| `EmptyState` | `cameraAvailable: boolean` | `camera` / `album` |
| `CameraSheet` | ——（v-if 由 App 控制） | `captured(file: File)` / `close` / `fallbackAlbum` |
| `PreviewConfirm` | `imageFile: File`、`phase: 'preview' \| 'recognizing' \| 'error'`、`error?: ApiError` | `confirm` / `retake` / `cancel` / `retry` / `reselect` |
| `LoadingOverlay` | `text?: string`（默认 L1 文案） | —— |

| `ErrorPanel` | `error: ApiError` | `retry` / `reselect` |

- `PreviewConfirm` 内部按 `phase` 切换：`recognizing` → 覆盖 `LoadingOverlay` ＋ 按钮禁用（U2）；`error` → 原按钮组隐藏、图下渲染 `ErrorPanel`（U3）；
- `CameraSheet` 自持 `<video>` 与取流生命周期，内部消化取流失败提示（D3）＋"改用相册上传"出口。

### 3.4 composables

**useCamera**（功能设计 §2.2/§2.3）：

- `detectCameraAvailable(): boolean`——`navigator.mediaDevices?.getUserMedia` 存在且 `isSecureContext`，只探测不调流；
- `openStream(video)`——`getUserMedia({ video: { facingMode: 'environment' } })`（U7）；
- `captureFrame(video): Blob`——video 原分辨率绘入 canvas；
- `stopStream()`——**立即 stop 全部 track**（U8），截帧与关闭两条路径都调；
- 失败分类 `denied / no_device / unknown` → CameraSheet 内展示 D3 文案。

**useCompress**（功能设计 §2.5，U10）：

```
compressImage(blob, name): Promise<File>
  1. createImageBitmap(blob, { imageOrientation: 'from-image' })   // T12：防 EXIF 旋转
  2. 长边 >1280 等比缩放，否则原尺寸
  3. canvas 先铺白底再绘制（PNG 透明通道转 JPEG 防黑底）
  4. toBlob('image/jpeg', 0.8) → new File(..., name, { type: 'image/jpeg' })
```

### 3.5 api.ts

```ts
const RECOGNIZE_TIMEOUT_MS = 35_000   // 功能设计 §4：后端 30s ＋ 网络余量
```
